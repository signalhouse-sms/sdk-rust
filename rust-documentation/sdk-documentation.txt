================================================================================
                    SIGNALHOUSE RUST SDK DOCUMENTATION
================================================================================

INSTALLATION
--------------------------------------------------------------------------------
  Add to your Cargo.toml:

  [dependencies]
  signalhouse-sms = "1.5.1"
  tokio = { version = "1", features = ["full"] }


INITIALIZATION
--------------------------------------------------------------------------------
  use signalhouse_sms::SignalHouseClient;

  let client = SignalHouseClient::new(
      "your-api-token",
      "https://v2.signalhouse.io",
  )?;

  Required options:
    - api_key   (&str)  JWT token or service user token for authentication
    - base_url  (&str)  API base URL

  SignalHouseClient::new returns a Result and will return an Err if api_key
  or base_url is empty.


PER-REQUEST TOKEN OVERRIDE
--------------------------------------------------------------------------------
  Every SDK method accepts an optional RequestOptions parameter to override
  the default api_key for that single request.

  Example:
    use signalhouse_sms::{RequestOptions, domains::messages::GetMessagesParams};

    let response = client.messages.get_messages(
        GetMessagesParams { page: Some(1), limit: Some(10), ..Default::default() },
        Some(RequestOptions { token: Some("user-specific-jwt-token"), ..Default::default() }),
    ).await?;

  The per-request token takes precedence over the api_key provided at
  initialization. The original api_key remains unchanged.


CUSTOM HEADERS
--------------------------------------------------------------------------------
  Pass additional headers via the RequestOptions.headers field:

  Example:
    use std::collections::HashMap;
    use signalhouse_sms::{RequestOptions, domains::numbers::GetPhoneNumbersParams};

    let mut custom_headers = HashMap::new();
    custom_headers.insert("X-Request-Id".to_string(), "req_abc123".to_string());

    let response = client.numbers.get_phone_numbers(
        GetPhoneNumbersParams { page: Some(1), limit: Some(20), ..Default::default() },
        Some(RequestOptions { headers: Some(custom_headers), ..Default::default() }),
    ).await?;


IDEMPOTENT REQUESTS
--------------------------------------------------------------------------------
  Set RequestOptions.idempotency_key to make a create, update or delete safe
  to retry. The SDK sends it as the Idempotency-Key header. A retry with the
  same key and the same request replays the first response, marked with the
  response header Idempotent-Replayed: true, instead of running the request
  again.

  - Use a new key (a UUID is recommended) for each new operation, and reuse
    it only to retry that exact request.
  - Keys are scoped to the authenticated user and kept for 24 hours.
  - Reusing a key for a different request returns 422; retrying while the
    first request is still running returns 409 with Retry-After.
  - The SDK never creates a key for you. GET requests ignore it, and the
    Voice service does not support it.

  Example:
    use signalhouse_sms::RequestOptions;

    let response = client.subgroups.create_subgroup(
        &serde_json::json!({ "groupId": "G0000001", "subgroupName": "Support" }),
        Some(&RequestOptions {
            idempotency_key: Some("6f1c2a4e-8b3d-4c5e-9f70-1a2b3c4d5e6f".into()), // a UUID you generate
            ..Default::default()
        }),
    ).await?;

    Returns { groupId, required, status, details, submittedAt, reviewedAt,

    subgroup_id is required (400 without it). subgroup_id: Option<&str>,

    Returns the get_business_verification shape, plus subgroupId when the
    business verification belongs to that one subgroup.

  submit_business_verification_for_subgroup(group_id, details, subgroup_id,

TEMPLATES  (client.templates)
--------------------------------------------------------------------------------
  Versioned message templates on /template. Every route is 404 while the API's
  RCS switch is off.
  Every call takes group_id (query on reads, body on JSON writes, form field on
  upload). `body` is the raw RcsTemplateBody as &Value ({channel: "rcs",
  contentFormat: "rcs.blocks.v1", content: {blocks}, variables, defaults,
  fallback}), sent verbatim. Writes honor RequestOptions.idempotency_key and
  apply directly (last write wins). Writing to an archived template is 409
  TEMPLATE_ARCHIVED; a name already in use is 409 TEMPLATE_NAME_TAKEN.

  create(group_id, name, body, tag,
      options) -> Result<SignalHouseResponse>
    POST /template. Creates draft version 1; returns 201 {head, version}.

  list(GetTemplatesParams { group_id, state, channel,
      tag, search, sort_by, sort_order, page, limit },
      options) -> Result<SignalHouseResponse>
    GET /template. state DRAFT|PUBLISHED|ARCHIVED, sort_by
    name|createdAt|updatedAt; limit default 25, max 100. Returns
    {data, total, page, limit} of summaries (head + state, hasUnpublishedChanges).

  get(template_id, group_id, version,
      options) -> Result<SignalHouseResponse>
    GET /template/:templateId. version is a positive integer, "draft" or
    "published"; None returns the published version, else the draft. An
    explicit version never falls back (404).

  update(UpdateTemplateParams { template_id, group_id,
      name, tag, body }, options) -> Result<SignalHouseResponse>
    PUT /template/:templateId. Edits the draft, creating one from the
    published version if needed. Unset fields are omitted. tag: None leaves it
    unchanged, Some(None) sends null to clear it. body is a full replacement.

  publish(template_id, group_id,
      options) -> Result<SignalHouseResponse>
    POST /template/:templateId/publish. Publishes the current draft.
    No draft is 409 NO_DRAFT; a draft that changed while it was being
    published is 409 DRAFT_CHANGED (publish again); an incomplete draft is 400
    {code: "TEMPLATE_INVALID", errors, warnings}.

  archive(template_id, group_id,
      options) -> Result<SignalHouseResponse>
    POST /template/:templateId/archive. Returns the head.

  versions(template_id, group_id, page, limit,
      options) -> Result<SignalHouseResponse>
    GET /template/:templateId/versions. Version summaries, no bodies.

  validate(template_id, group_id, body, version,
      options) -> Result<SignalHouseResponse>
    POST /template/:templateId/validate. Pass exactly one of body or
    version (a numeric version is sent as a number). Writes nothing; returns
    {valid, contentHash, validatorVersion, errors, warnings}.

  capabilities(group_id, channel, provider,
      options) -> Result<SignalHouseResponse>
    GET /template/capabilities. channel defaults to "rcs"; provider
    infobip|sinch adds provider limits and unsupported features.

  upload_media(group_id, file, file_name,
      options) -> Result<SignalHouseResponse>
    POST /template/media, multipart fields file + groupId. Returns 201
    {mediaId, groupId, url, bytes, mimeType, kind, width, height, createdAt}.

================================================================================
                          MULTIPART REQUESTS
================================================================================

  The following methods use multipart/form-data automatically:

    - client.messages.send_mms(...)
    - client.messages.send_group_message(...)
    - client.landings.create_landing(...)
    - client.landings.update_landing(...)
    - client.brands.submit_appeal(...)
    - client.templates.upload_media(...)

  You do not need to construct reqwest::multipart::Form manually. Pass file
  data as byte vectors or file paths and the SDK builds the multipart form
  data internally.


================================================================================
                          QUERY STRING HELPERS
================================================================================

  The SDK automatically constructs query strings from params struct fields.
  Any field set to None is excluded, so you only need to set the filters
  you care about. Use ..Default::default() to leave all other fields as None.

  Example:
    // Only sends ?status=FAILED&page=1&limit=50
    let messages = client.messages.get_messages(
        GetMessagesParams {
            status: Some("FAILED"),
            page: Some(1),
            limit: Some(50),
            ..Default::default()
        },
        None,
    ).await?;


================================================================================
                             VALIDATION
================================================================================

  The SDK validates required parameters client-side before making any HTTP
  request. If a required parameter is missing or empty, the SDK returns a
  SignalHouseError::Validation error immediately -- no network request
  is made.

  Validation errors:
    - Variant: SignalHouseError::Validation { field, message }
    - Message: "Missing required parameter: <field_name>"

  Match with:
    match err {
        SignalHouseError::Validation { field, message } => { ... }
        _ => { ... }
    }


================================================================================
                           ERROR HANDLING
================================================================================

  The SDK uses a standardized response type. HTTP errors are NOT returned
  as Rust errors -- they are returned as SignalHouseResponse values with
  success == false.

  Success response:
    SignalHouseResponse { success: true, data: Some(Value), status: 200 }

  Error response:
    SignalHouseResponse { success: false, error: Some("Error message"), status: 400 }

  Error types summary:

    Source                    Behavior                             How to Handle
    -----------------------------------------------------------------------
    Missing required param    Returns Err(SignalHouseError)        match on Result
    HTTP 4xx/5xx from API     Returns Ok(SignalHouseResponse)      Check response.success
    Network failure           Returns Err(SignalHouseError)        match on Result

                       COMPLETE INTEGRATION EXAMPLE
================================================================================

  use actix_web::{web, App, HttpServer, HttpRequest, HttpResponse};
  use serde::{Deserialize, Serialize};
  use signalhouse_sms::{SignalHouseClient, RequestOptions};
  use signalhouse_sms::domains::messages::{GetAnalyticsParams, SendSmsParams};
  use signalhouse_sms::domains::numbers::GetPhoneNumbersParams;
  use signalhouse_sms::error::SignalHouseError;
  use std::env;
  use std::sync::Arc;

  #[derive(Deserialize)]
  struct NotifyRequest {
      recipient_number: String,
      message: String,
      sender_number: String,
  }

  #[derive(Deserialize)]
  struct DeliveryStatus {
      message_id: String,
      status: String,
  }

  #[derive(Deserialize)]
  struct PaginationQuery {
      page: Option<u32>,
      limit: Option<u32>,
  }

  #[derive(Deserialize)]
  struct AnalyticsQuery {
      start_date: Option<String>,
      end_date: Option<String>,
      campaign_id: Option<String>,
  }

  struct AppState {
      client: SignalHouseClient,
  }

  // Send an SMS notification
  async fn notify(
      state: web::Data<Arc<AppState>>,
      body: web::Json<NotifyRequest>,
  ) -> HttpResponse {
      let base_url = env::var("BASE_URL").unwrap_or_default();

      let result = state.client.messages.send_sms(
          SendSmsParams {
              sender_phone_number: &body.sender_number,
              recipient_phone_numbers: vec![body.recipient_number.clone()],
              message_body: &body.message,
              status_callback_url: Some(&format!("{}/api/delivery-status", base_url)),
              enable_shortlink: None,
          },
          None,
      ).await;

      match result {
          Ok(response) if response.success => HttpResponse::Ok().json(response.data),
          Ok(response) => HttpResponse::build(
              actix_web::http::StatusCode::from_u16(response.status as u16)
                  .unwrap_or(actix_web::http::StatusCode::INTERNAL_SERVER_ERROR)
          ).json(serde_json::json!({"error": response.error})),
          Err(SignalHouseError::Validation { message, .. }) => {
              HttpResponse::BadRequest().json(serde_json::json!({"error": message}))
          }
          Err(_) => HttpResponse::InternalServerError()
              .json(serde_json::json!({"error": "Internal server error"})),
      }
  }

  // Receive delivery status callbacks
  async fn delivery_status(body: web::Json<DeliveryStatus>) -> HttpResponse {
      println!("Message {} status: {}", body.message_id, body.status);
      HttpResponse::Ok().json(serde_json::json!({"received": true}))
  }

  // List phone numbers with per-request token override
  async fn list_numbers(
      state: web::Data<Arc<AppState>>,
      req: HttpRequest,
      query: web::Query<PaginationQuery>,
  ) -> HttpResponse {
      let user_token = req.headers()
          .get("Authorization")
          .and_then(|v| v.to_str().ok())
          .map(|s| s.trim_start_matches("Bearer "))
          .unwrap_or("");

      let result = state.client.numbers.get_phone_numbers(
          GetPhoneNumbersParams {
              page: Some(query.page.unwrap_or(1)),
              limit: Some(query.limit.unwrap_or(20)),
              ..Default::default()
          },
          Some(RequestOptions {
              token: Some(user_token),
              ..Default::default()
          }),
      ).await;

      match result {
          Ok(response) if response.success => HttpResponse::Ok().json(response.data),
          Ok(response) => HttpResponse::build(
              actix_web::http::StatusCode::from_u16(response.status as u16)
                  .unwrap_or(actix_web::http::StatusCode::INTERNAL_SERVER_ERROR)
          ).json(serde_json::json!({"error": response.error})),
          Err(_) => HttpResponse::InternalServerError()
              .json(serde_json::json!({"error": "Internal server error"})),
      }
  }

  // Get message analytics
  async fn analytics(
      state: web::Data<Arc<AppState>>,
      query: web::Query<AnalyticsQuery>,
  ) -> HttpResponse {
      let result = state.client.messages.get_analytics(
          GetAnalyticsParams {
              start_date: query.start_date.as_deref(),
              end_date: query.end_date.as_deref(),
              campaign_id: query.campaign_id.as_deref(),
              ..Default::default()
          },
          None,
      ).await;

      match result {
          Ok(response) if response.success => HttpResponse::Ok().json(response.data),
          Ok(response) => HttpResponse::build(
              actix_web::http::StatusCode::from_u16(response.status as u16)
                  .unwrap_or(actix_web::http::StatusCode::INTERNAL_SERVER_ERROR)
          ).json(serde_json::json!({"error": response.error})),
          Err(_) => HttpResponse::InternalServerError()
              .json(serde_json::json!({"error": "Internal server error"})),
      }
  }

  #[actix_web::main]
  async fn main() -> std::io::Result<()> {
      let client = SignalHouseClient::new(
          &env::var("SIGNALHOUSE_API_KEY").expect("SIGNALHOUSE_API_KEY must be set"),
          "https://v2.signalhouse.io",
      ).expect("Failed to create SignalHouse client");

      let state = Arc::new(AppState { client });

      println!("Server running on port 3000");
      HttpServer::new(move || {
          App::new()
              .app_data(web::Data::new(state.clone()))
              .route("/api/notify", web::post().to(notify))
              .route("/api/delivery-status", web::post().to(delivery_status))
              .route("/api/numbers", web::get().to(list_numbers))
              .route("/api/analytics", web::get().to(analytics))
      })
      .bind("0.0.0.0:3000")?
      .run()
      .await
  }


REGISTRATIONS AND REGIONAL REPORTING
--------------------------------------------------------------------------------
A registration is what a jurisdiction (or its provider) requires before a sender
may message. One model covers every jurisdiction: `region` is the jurisdiction
(US, GB, CA, AU; any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) and `type` selects the shape of `data`.
Types: TEN_DLC_BRAND, TEN_DLC_CAMPAIGN, TOLL_FREE_BRAND, TOLL_FREE_CAMPAIGN,
SHORT_CODE_BRAND, SHORT_CODE_PROGRAM, SHORT_CODE_LEASE (not available), VIRTUAL_LONG_CODE (UK) and ALPHANUMERIC_SENDER_ID (UK). Kinds: identity, program, sender. Channels: tenDLC, tollFree,
shortCode, virtualLongCode, alphanumeric.

Start with the catalog. GET /registration/catalog?region= returns {region,
jurisdiction, sendingRequiresRegistration, registeredThrough, provisioning, types:[{type, kind,
channel, provider, bundles, quantity:{min,max}, requiresParent, available}]}.
registeredThrough is "registration" (use this API), "brandsAndCampaigns" (the US:
register through the Brands and Campaigns APIs) or null (nothing to register, e.g.
Canada). An unlisted country requires registration and offers no types.
Quote and submit only a type whose `available` is true; other types answer 400.

GET /registration/quotes?region=&type=&quantity= (1-100, default 1) returns
{data:[quotes]}, one quote per capability bundle: {capabilities, quantity,
currency, setupAmount, monthlyAmount, totalSetupAmount, totalMonthlyAmount,
etaDays}. Amounts are integer microdollars; setupAmount/monthlyAmount are per
sender and the totals cover the quantity. groupId is optional and staff-only.

Submit on POST /registration (201) with region, type, subgroupId,
capabilities (one of the type's bundles) and data. Set RequestOptions.idempotency_key to make a
retry safe (see IDEMPOTENT REQUESTS). Worked example, UK Virtual Long Code: type "VIRTUAL_LONG_CODE",
capabilities ["SMS"] or ["SMS","VOICE"], data {quantity (1-100), useCases (1-10
strings), voice?}. The voice dossier is required exactly when capabilities
include VOICE: companyName, companyPhone, companyWebsite, companyEmail,
address {line1,line2?,city,postalCode,country}, companyDescription,
campaignName, campaignDescription, optInMethods (WEB|KEYWORD|VERBAL),
optOutKeywords (STOP and UNSUBSCRIBE), callTypes (LANDLINE|LOCAL|INTERNATIONAL),
callsPerDay (1-5), callDurationMinutes (1-10, 15, 30, 45 or 60) and termsUrl.

Worked example, UK alphanumeric sender ID: region "GB", type
"ALPHANUMERIC_SENDER_ID", capabilities ["SMS"], data {requestedSenderId (3-11
letters, digits, spaces, dots or dashes; at least one letter), trafficOrigin
(LOCAL: headquartered in the UK | INTERNATIONAL), trafficType (TRANSACTIONAL |
PROMOTIONAL), companyName, companyCountry, companyWebsite (http/https), industry,
messageExample, senderRelationship? (required when requestedSenderId differs from
companyName)}. quantity is always 1; the quote is one ["SMS"] bundle, 6000000
setup and 6000000 monthly by default. Once the registration is APPROVED,
data.phoneNumbers holds the granted sender (e.g. ["ACME"]); pass it as the sender
to send SMS to UK recipients. The server appends "\nOpt out: sihou.io/o/{code}"
to every message from it, counted in segments and in the estimate.

GET /registration accepts groupId, subgroupId, region, type, kind, status,
parentRegistrationId, phoneNumber (filter to registrations holding this phone
number), sortBy (createdAt (default), subgroupId, registrationId, region or
status), sortOrder (asc or desc (default)), page and limit (max 100) and returns
{data,totalCount,page,limit}.
Region and status each take one value or a comma-separated list (e.g.
status: Some("PENDING_PROVIDER,APPROVED")).
GET /registration/:registrationId returns
{registrationId, groupId, subgroupId, region, type, kind, channel, provider,
externalId, parentRegistrationId, status, stage, capabilities, submittedAt,
approvedAt, expiresAt, review:{decision,reviewedAt,reason}, data:{...type
fields}, history:[{status,stage,actor,actorType,timestamp,reason}], createdAt,
updatedAt}. For VIRTUAL_LONG_CODE, data also carries phoneNumbers, the numbers
allocated so far. Statuses: DRAFT, SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
SIGNAL_HOUSE_REJECTED, SUBMITTING, PENDING_PROVIDER, NEEDS_INFORMATION,
PAYMENT_REQUIRED (the setup fee could not be funded; retried hourly), APPROVED,
REJECTED, CANCELLED, PENDING_DELETE, DELETED, EXPIRED, RECONCILIATION_REQUIRED.
`stage` is the provider's step inside a status. Never send from a sender whose
registration is not APPROVED.

DELETE /registration/:registrationId cancels a registration (roles api, admin,
developer, user). Allowed from SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
PENDING_PROVIDER, NEEDS_INFORMATION, PAYMENT_REQUIRED and APPROVED (409
otherwise). Numbers already allocated stay on the account and stop sending.

Staff only (the admin namespace exists only when the client enables admin, and
enabling it grants no server permission):
POST /:registrationId/review {action:"APPROVE"|"REJECT",reason?}; REJECT needs reason.
POST /:registrationId/corrections {reason,data} saves the type's correctable
fields (VIRTUAL_LONG_CODE: useCases, voice?) while the provider waits; owner,
quantity, bundle and provider order are fixed.
POST /:registrationId/numbers {phoneNumber} allocates a provider-owned number
through the recovery path.
POST /:registrationId/reconcile {externalId} links the provider order that was
placed after an ambiguous submission; never place a second order to retry.
GET /:registrationId/application?format=json returns {filename,contentType,base64};
decode base64 before saving the document.

Regional reporting: GET /message, /message/analytics, /message/analytics/detail,
/message/analytics/by-subgroup, /message/analytics/by-error-code, /message/dnc and
/message/dnc/analytics accept region and regionScopes; GET
/message/analytics/filter-options accepts region only. region is US, GB or CA
(any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) as a single value, a repeated parameter or a CSV.
regionScopes is a JSON array of OR-ed branches {region, channels, brandId?,
campaignId?, phoneNumber?} with channels from tenDLC, virtualLongCode, tollFree,
shortCode and p2p; [] matches nothing and omitting both keeps the existing scope.
Example:
[{"region":"US","channels":["tenDLC"],"brandId":["BUS1"]},
 {"region":"GB","channels":["virtualLongCode"],"phoneNumber":["447400123456"]}]
GET /message always accepts them; the analytics and DNC reads accept them only
where the environment serves hourly analytics and reject them with a 400 elsewhere.

get_analytics, get_analytics_detail, get_analytics_throughput and
get_dnc_analytics accept registration_id (a single id or a comma-separated list,
like campaign_id): filter to traffic attributed to these registrations (hourly
analytics only; a 400 while hourly reads are off). Except on
get_analytics_throughput, which has no phoneNumber filter, a phoneNumber filter
takes precedence. get_phone_numbers accepts a single registration_id to list the
numbers provisioned under that registration.

get_analytics_by_subgroup, get_analytics_by_error_code and get_dnc_records accept
registration_id the same way, with the same hourly-only rule and precedence.
get_messages accepts registration_id in every environment: it filters to messages
attributed to those registrations, and a phone_number filter narrows further. Every
method returns 400 when registration_id is combined with campaign_id.

get_analytics_filter_options returns each phone number with its type (TOLL_FREE,
SHORT_CODE, ALPHANUMERIC, VIRTUAL_LONG_NUMBER, and older local-number spellings) and
country (ISO-2), null when unknown. TOLL_FREE, SHORT_CODE and ALPHANUMERIC are channels
by type; a US number of any other type is 10DLC and a non-US one is a Virtual Long Code.
It also returns carriers, a plain array of carrier name strings.

UK sending is SMS only, from a +44 virtual long code to GB mobile recipients; MMS
and group MMS are unavailable. POST /message/estimate accepts a +44 sender
(recipients 10-15 digits) and returns region "GB", or "CA" for a Canadian sender.
A READY alphanumeric sender ID (e.g. "ACME") also sends SMS to UK recipients only;
its estimate includes the opt-out footer.
